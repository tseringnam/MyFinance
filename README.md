# My Finance — AWS Amplify Gen 2

A GitHub-ready budget app: React + Vite frontend, Cognito email/Google login,
AppSync API, and DynamoDB storage. It replaces the previous Cloudflare/Sites
backend. It is a separate project; the currently hosted app is unchanged.

## Included behavior

- Bright responsive budget interface with editable income, expenses, investments.
- Monthly surplus = monthly income minus monthly expenses; annual projection × 12.
- Investments are current balances, separate from spending and annual income.
- Every new account starts blank. No personal spreadsheet values are included.
- Explicit Save changes, sign-out confirmation for unsaved edits, and error recovery.
- Backend owner-only access; the owner field cannot be edited to transfer access.
- Email signup/reset and Google login through Cognito (not ChatGPT).
- Home Screen manifest for iPhone. This is a web app, not an App Store binary.

## 1. Upload to GitHub

Create a **private**, empty repository named `my-finance-amplify` in your own
GitHub account. Extract this download and upload the **contents** of this folder,
including `package-lock.json`, `.gitignore`, `amplify.yml`, `amplify/`, and `src/`,
to the repository root. Do not upload `node_modules` or `dist`.

Or run these commands in the extracted project on your Mac (replace the URL):

```bash
git init
git add .
git commit -m "Add Amplify budget app"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/my-finance-amplify.git
git push -u origin main
```

Node.js 22.13 or newer is required. Dependencies are pinned by the lockfile.

## 2. Create Google OAuth credentials

Users will create an account, verify their email, and sign in with a password. Gmail addresses work normally.
**Web application**. Request only openid, email, profile. Record its client ID and
client secret. If Google keeps the app in testing, add intended users as test
users; use its publishing process before inviting the general public.

**Never put the client secret in GitHub, frontend code, or VITE_* variables.**
After the AWS backend deploys, you will add its exact Cognito callback URL to
Google (step 4). A first deployment can finish before that callback is configured,
but Google login will not work until step 4 is complete.

## 3. Deploy from Amplify

1. Sign into your AWS account and select the region where you want budget data.
2. Open Amplify, create a new app, select GitHub, and authorize repository access.
3. Select this repository and the `main` branch. Use the checked-in `amplify.yml`
   (Gen 2 fullstack pipeline, Vite frontend, `dist` output).
4. Configure the Amplify service role for Gen 2 backend deployment. Use Amplify's
   offered role creation flow; do not place AWS access keys in this repository.
5. In the app/branch secret settings add secrets named exactly:
   `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. Some console flows expose these
   after the app is created: add them, then redeploy if the first build fails.
6. Set the build environment's Node runtime to 22 or newer if it is not already.
7. Deploy. `ampx pipeline-deploy` creates Cognito, AppSync, DynamoDB, and generates
   `amplify_outputs.json` for the frontend build.

The auth configuration automatically uses the standard branch address
`https://main.<app-id>.amplifyapp.com/` using Amplify's build environment. Verify
it matches the deployed address. For a custom domain, branch name containing
slashes, or any different URL, set the Amplify build environment variable
`APP_URL` to the actual HTTPS address **with a trailing slash**, then redeploy.
This variable is not a secret. Only the chosen URL is allowed as a Cognito
callback/logout address. Local sandbox defaults to `http://localhost:5173/`.

## 4. Complete Google sign-in

In Cognito, locate the user pool generated by this Amplify branch. Find its
managed-login domain. In your Google OAuth web client configure:

- Authorized JavaScript origin: `https://YOUR_COGNITO_DOMAIN`
- Authorized redirect URI: `https://YOUR_COGNITO_DOMAIN/oauth2/idpresponse`

Use the full actual domain, such as a host ending in
`.auth.us-east-1.amazoncognito.com`. Do **not** use the app's Amplify URL for this
Google redirect URI. Google redirects to Cognito; Cognito redirects to `APP_URL`.

Visit your Amplify address and choose Google sign-in. Email/password signup is
also available. Signing up separately with email and Google can create separate
accounts; automatic account linking is not implemented.

## 5. Verify before sharing

Use two accounts in separate browser profiles:

1. Account A starts with empty Income, Expenses, Investment tabs.
2. Add income 1000, expenses 200, investment balance 5000. Save and refresh.
3. Check monthly surplus 800, yearly surplus 9600, investment balance 5000.
4. Account B starts blank and cannot see A's entries.
5. For a backend isolation check, use B's authenticated Amplify client to request
   A's Budget ID (`A`'s Cognito sub). It must return no record or authorization
   error; updating/deleting A's record must be rejected. Do not enable public API
   key access or broad authenticated-user access to make this test pass.
6. Test save failures, sign-out, password reset, Google redirects, and Safari on
   iPhone. In Safari choose Share > Add to Home Screen.

Frontend hiding is not the security boundary: authorization is enforced by
AppSync owner rules on every data operation. AWS administrators with appropriate
IAM permissions can inspect records; this is not end-to-end encryption.

## Local development

```bash
npm ci
npm test
npm run build
```

Without a generated `amplify_outputs.json`, the app displays a setup screen.
No fake AWS credentials are included. For a real development backend, configure
your AWS CLI profile and run:

```bash
npx ampx sandbox secret set GOOGLE_CLIENT_ID --profile YOUR_PROFILE
npx ampx sandbox secret set GOOGLE_CLIENT_SECRET --profile YOUR_PROFILE
npx ampx sandbox --profile YOUR_PROFILE
```

Enter secret values at the prompts, not in commands. In another terminal run
`npm run dev`. Configure the sandbox Cognito callback in Google separately.
Delete an unused sandbox with `npx ampx sandbox delete --profile YOUR_PROFILE`.
Sandboxes provision real AWS resources and may incur charges.

## Design limits and operations

- A single JSON budget document is stored per account, with ID equal to its
  Cognito user ID. Owner metadata is generated by Amplify. Arrays are capped at
  300 entries per section in the UI; amounts must be finite and nonnegative.
- Budget validation runs in the app. The API JSON field does not independently
  enforce the budget shape, so malformed self-owned data can require admin repair.
- Saving the same account on multiple devices uses **last successful save wins**.
  Avoid editing simultaneously. Transactional version conflict handling is not
  implemented; this is a material difference from the old app's revision checks.
- No offline saving, bank connections, admin dashboard, invitation email service,
  account linking, or native iOS build is included.
- Anyone eligible for signup can create their own private budget. Public signup
  is intentional here; allowlist-only enrollment would require an additional rule.
- Existing budgets are not automatically migrated. Reenter your values after
  signing in, or add an explicit import flow later.
- Configure backup/restore and retention according to your needs before relying
  on the database. Cognito account deletion does not automatically delete the
  separate budget document; an admin must delete both for a deletion request.
- Monitor charges in AWS Billing. Hosting, backend resources, Google configuration,
  and domain management are in your accounts; ChatGPT is not required to run it.
